# 拡張間の定義取得・模擬操作 試作

二つの独立した試作拡張を使い、対象拡張に同梱されたJSON定義の取得と固定された模擬操作の要求・応答を確認できます。加えて、THE SESSION TOOLSを選択すると試作APIで実際にテンポを5上げます。音声サービス・マイク・ネットワーク通信は使用しません。JSON・メッセージ形式は試作専用で、正式な契約ではありません。

1. `about:debugging#/runtime/this-firefox` から、`target/manifest.json` を一時読み込みします。
2. 続けて `manager/manifest.json` を一時読み込みします。
3. Firefoxの拡張メニューで「Foxbook 操作管理 試作」を開き、**定義を取得** を押します。「ダミーメトロノーム」の定義が表示されることを確認します。
4. **模擬操作を送信** を押し、「模擬操作を受け付けました」が表示されることを確認します。
5. 必要に応じて対象拡張を無効化し、取得時に接続エラーが表示されることを確認します。

## THE SESSION TOOLSの実操作

1. THE SESSION TOOLSを再読み込みし、The Sessionのページも再読み込みします。
2. **そのページを前面にした状態**で「Foxbook 操作管理 試作」を開き、対象を **THE SESSION TOOLS（実際のテンポ変更）** に切り替えます。
3. **定義を取得** を押し、続けて **テンポを5上げる（実操作）** を押します。メトロノームのBPMが5増え、画面にも結果が表示されます。300 BPMではそれ以上増えません。
4. ページが非アクティブの場合は `TARGET_INACTIVE` を返し、BPMを変更しません。接続エラーが出る場合はTHE SESSION TOOLSと操作管理の試作を再読み込みしてください。

対象タブを残したまま別タブを前面にして実行すると `TARGET_INACTIVE` が表示され、BPMは変わりません。対象拡張を無効化した場合は定義取得で接続エラーになります。実行中は操作ボタンと対象切替を無効にし、通信失敗時は操作済みの可能性を表示します。自動再送はしません。定義取得・操作要求は5秒で時間切れにします。操作が時間切れになっても対象側の処理は取り消されず、後から実行される可能性があります。対象の状態を確認し、必要なら定義を再取得してください。時間切れ後の遅延実行が起きないことは保証できません。利用者は対象拡張の無効化時に操作ボタンの無効化と接続エラー表示、対象タブの非アクティブ時に `操作失敗：TARGET_INACTIVE` を確認しました。端末・Firefoxバージョン、非アクティブ時のBPM値と、通信失敗時の結果不明表示は未確認です。

操作管理の拡張IDは実験専用です。利用者がクリックした場合にのみ操作を送ります。通常の音声コマンド処理やマイク制御とは接続していません。

対象側は送信元の拡張IDを検証し、固定されたバージョン・メッセージ形式・コマンドIDだけを受け付けます。不正な送信元・不正な形式の拒否は自動試験で確認します。実際の拡張ID、API仕様、対象の発見、動的な引数、正式なタイムアウト値と許可方式は未決定です。

```bash
node tests/test_assistant_exchange_probe.cjs
```

## 遅延・無応答のFirefox試験

この試験はダミー対象を使用し、THE SESSION TOOLSのテンポを変更しません。Firefoxのバージョンと端末を記録します。対象・管理の両拡張を再読み込みし、拡張メニューの「Foxbook 操作対象 試作」をクリックして試験設定を別タブで開きます。管理ポップアップを開く前に試験設定でモードを選び、操作記録を消去します。モード変更と消去の完了を確認してから管理を開き、対象に「ダミー」を選んでください。設定ページに戻る際、管理ポップアップは閉じます。

| モード | 手順と期待結果 |
| --- | --- |
| 正常応答 | 定義取得後に模擬操作を送信。成功表示と記録1件を確認する。 |
| 操作後、8秒遅れて応答 | 定義取得後に送信し、ポップアップを開いたまま待つ。約5秒で結果不明、操作無効となり、8秒以降も成功表示に変わらないことを確認する。設定ページに戻り記録1件を確認する。 |
| 8秒遅れて操作・応答 | 同様に送信し、時間切れ表示を確認してから8秒以上待つ。設定ページで操作が後から記録されるか確認する。 |
| 操作要求に無応答 | 定義取得後に送信。約5秒で結果不明と操作無効を確認し、設定ページで記録0件を確認する。 |
| 定義取得に無応答 | 定義取得を押し、約5秒で接続エラーと操作無効を確認する。 |

操作の要求中は操作ボタン・定義取得・対象選択が無効になります。無効化中は再送せず、時間切れ後は対象の状態を確認してから必要に応じて定義を再取得します。時間切れやポップアップを閉じる操作は対象側の処理を取り消しません。保留中の処理がある場合は十分待ってから次の試験の記録を消去してください。

追加試験では「8秒遅れて操作・応答」を選び、送信直後に管理ポップアップを閉じ、8秒以上待って操作記録を確認します。対象のイベントページの停止などにより、操作が実行されない可能性もあります。結果をそのまま記録し、どちらの場合も取消保証の証明にはしません。試験後はモードを「正常応答」に戻します。

利用者は2026-11-19に上記5モードが期待どおりで、遅延実行の送信直後に設定ページへ移動した場合も約8秒後に記録が表示されたと報告しました。端末・Firefoxバージョンは未記録です。
